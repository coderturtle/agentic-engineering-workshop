**1. The red-herring noise gives itself away in-band, undermining the "genuine curation tradeoff" claim.** `config/tax_rates.yaml` opens with `# Red herring: per-state tax rate tables... group_expenses_by_month never reads this file.` This isn't isolated: every noise file self-announces — `legacy_export.py`'s docstring says "A red herring by inclusion... it looks like it might matter to a nervous reader and does not," and all three stale docs open with `> Stale, predates the current CLI. Not maintained.` The module claims (README line 29) the tax config "looks like it could plausibly affect expense totals" and requires real judgment to exclude, and the Skill (`SKILL.md` step 4) instructs "confirm with a real search... not a skim." In practice a plain `head` or a single `grep -l "red herring\|Stale\|Nothing in"` across the tree identifies 100% of the noise instantly, with zero need to trace the verification path. The exercise doesn't test the judgment it claims to test — it tests whether you read file headers.

**2. Line-count is a weaker proxy for context-window pressure than the module treats it as, and the fixture itself proves it.** Measuring the bloated variant: `config/tax_rates.yaml` runs 24 chars/line, `README.md` 51, `CHANGELOG.md` 53 — over 2x variance in token-density per line within the same fixture. `context-budget.sh` computes chars and a rough token estimate but the actual gate (rubric criterion 1: "at or under 2,000 lines") is lines-only. A curator who keeps short-line files stays "under budget" while a curator with equivalent actual token content in long-line files does not — the reverse of what a context-window budget should reward. The script's own token estimate (~100,245 for the full bloated variant vs. 9,294 lines) is never surfaced as a checkable number anywhere in the rubric.
