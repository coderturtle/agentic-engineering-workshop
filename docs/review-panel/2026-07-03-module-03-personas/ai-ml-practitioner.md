# Persona: AI/ML Practitioner — Module 03 — 2026-07-03

## Finding 1 (primary): the reset-and-resume doesn't actually isolate reliance on the notes file

The exercise's central claim is that "the second session can only complete the task by reading the state the first one left behind" (README.md:30), and the dry-run's own writeup asserts phase 2 "completed the task correctly using only the on-disk notes file. This is the hardest criterion to fake and the one this exercise is actually testing" (`runs/.../README.md:23`). But that's asserted, not demonstrated. Phase 2 is invoked *as* the named sub-agent, whose definition (`receipts-category-summary.md`) already states the complete task in full — implement the function *and* wire the CLI flag. Combined with the fact that phase 2 is explicitly permitted, and required, to run `tests/test_by_category.py`, running that command alone reveals exactly what's done (function test passes) and what's left (CLI test fails on the missing flag) — with zero need to open `.receipts-category-progress.md`. Nothing in the progress file (`harness-work/.receipts-category-progress.md`) carries information that isn't already recoverable from the code diff plus the failing test — the one "decision" it records (keeping the `months` field name) is already baked into the code phase 1 wrote. So a capable agent could re-derive the remaining half of the task from the fixture itself, undermining the "state survives reset" claim this criterion is supposed to gate.

Notably, the module's own Stop condition text anticipates exactly this risk — "check what the second session could plausibly have known without the notes file" (README.md:53) — but the reference run never performs that ablation (e.g., rerunning phase 2 with the progress file deleted/withheld to confirm it fails or diverges). The reference implementation doesn't model the verification it asks learners to do.

## Finding 2 (secondary): translation table overstates enforcement parity

The sub-agent row (Sub-agent ↔ "Custom mode / rules-scoped chat" ↔ "Custom instructions scoped to a task") implies rough equivalence, but rubric criterion 1 depends on the boundary being "explicit in the sub-agent's own definition, not just followed by luck" — i.e., harness-enforced. Claude Code sub-agents enforce a tool/file scope; Cursor custom modes restrict which *tools* are enabled but don't enforce per-directory file-write scope, and Codex "custom instructions" are unenforced prompt text with no comparable sandboxing. The table doesn't flag this enforcement gap, which matters directly for the property this exercise is testing.
