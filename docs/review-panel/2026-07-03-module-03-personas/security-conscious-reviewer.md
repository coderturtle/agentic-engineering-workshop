# Persona: Security-Conscious Reviewer — Module 03 — 2026-07-03

This module's core exercise is scope-boundary design, so the gap between what's *taught* and what's *enforced* matters more here than elsewhere.

**The boundary is prose, not enforcement.** `.claude/agents/receipts-category-summary.md`'s frontmatter has only `name` and `description` — no `tools:` restriction, no path allowlist, nothing at the harness-config level that prevents the agent from reading/writing outside `receipts/` or running arbitrary commands. "You may read and edit files under `receipts/` only" is an instruction the agent is trusted to obey, not a boundary Claude Code enforces. The rubric half-acknowledges this ("the boundary is explicit in the sub-agent's own definition, not just followed by luck") but stops short of requiring any actual enforcement mechanism (a `tools:` allowlist, a permission rule, a sandboxed working directory) — "followed by luck" is exactly what a prose-only boundary is. A learner could satisfy this rubric item by writing a strongly-worded scope paragraph and nothing else.

**Verification is asymmetric.** The reset-and-resume criterion explicitly demands independent confirmation ("diff the working copy, or check what the second session could plausibly have known"). Bounded reach gets no equivalent instruction — nothing tells the learner to diff/`git status` *outside* `receipts/` to confirm the agent didn't wander. The dry-run's own README does this correctly (confirms `cli.py` byte-identical before phase 2) but that discipline isn't elevated into the rubric as a required check, so it's easy to copy the exercise without copying the verification habit.

**No transcript actually shipped.** The stop condition requires "a transcript," but `runs/2026-07-03-module-03-dry-run/` contains only a narrative README, a diff, and the progress file — no raw tool-call log. The module conflates "diff + command output" with "transcript," which is weaker evidence than it sounds like.

**Persistent state is trusted blindly.** The agent's instructions say to read `.receipts-category-progress.md` and "resume from where it says the work stands" with no guidance to treat its contents as untrusted data rather than authoritative instructions. Combined with unrestricted tool access, a stale or tampered notes file could steer a resumed session into unscoped action, and the module never flags this as a risk worth teaching.
