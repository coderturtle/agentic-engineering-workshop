# Critical Review: Is the Harness Hypothesis Actually Being Tested?

**Date:** 2026-07-11
**Reviewer:** independent adversarial pass (cold read of the repo; no involvement in any prior session; no prior finding taken as ground truth without re-derivation)
**Scope:** the specific claim in `docs/workshop-design.md` line 26 — "the harness *is* the classroom ... it should be read as a hypothesis this workshop is testing, not a settled claim" — versus everything the project has actually run, plus whatever else surfaced along the way.

---

## 1. Verdict

**The harness hypothesis is untested. Not partially tested — untested.** The claim is a comparative statement about human learning ("doing it inside a harness teaches better than a well-structured written guide"), and no human learner has ever attempted any module. Every piece of evidence in `runs/` — five module dry runs, two review-panel campaigns, a rubric-gaming discrimination test, a blind local-model judging panel, a Codex CLI second-harness spike, a local devstral student-gremlin spike — tests whether the *mechanism* functions: whether exercises are completable, whether the rubric discriminates gaming from good faith, whether a manifest is parseable by a second harness, whether write isolation holds. All of that is real and mostly well-executed, and the repo's prose is admirably honest about hedging the hypothesis (the initial review panel caught the one overclaim on day one, `docs/review-panel/2026-07-03-initial-design.md` line 27, and it was fixed). But honesty about the hedge is not a test of the claim, and — critically — **nothing in `docs/next-actions.md` (the project's own complete backlog, read in full) contains any item that would ever test it.** The backlog's open items (Phase B human confirmation, Phase C tv/MCP decision, second-workshop panel run, blind grading passes) all deepen mechanism validation. The actual test would be: a written-guide control version of one module (03 or 04), a handful of real practitioners from the stated audience (even n=4–6), random assignment, and a transfer task plus an explain-it-back measure a week later. Nothing resembling that exists, is planned, or is even named as missing. The project says it is "testing" the hypothesis; on the evidence, it is building and hardening the apparatus while the experiment itself has no start date and no design.

---

## 2. Findings, ranked

### Finding 1 (most important): The hypothesis has no test, no plan for a test, and the workshop as shipped cannot ever collect the data a test needs

- `docs/workshop-design.md` line 26 frames the hypothesis as something "this workshop is testing." It is not being tested; it is being assumed while adjacent things are tested. That distinction is stated nowhere.
- `docs/next-actions.md` (read end to end): zero backlog items involve a human learner, a written-guide comparison, or any learning-outcome measure. The closest items — Phase B (`docs/module-03-pilot-completion-plan.md`) and RISK-0004's residual ("no module has been checked by a human with zero involvement," `docs/risks.md` line 13) — are about the *maintainer* confirming evidence and about grading validity, not about anyone learning anything.
- Structurally worse: the product's own format forecloses data collection. It is a self-paced public repo with local grading by the learner's own agent (`docs/agent-native-interaction-plan.md` §2, deliberately and for good reasons), no submission channel, no telemetry, and no instrumented feedback path beyond a generic GitHub issues link (`README.md` line 49). Even if a thousand people cloned it tomorrow, the maintainer would learn nothing about whether the harness taught better than a guide would have. The hypothesis is not just untested; the shipped artifact has no sensor for it.
- What a real test looks like, concretely: (a) write the "well-structured written guide" version of Module 03 or 04 — the comparison arm the hypothesis explicitly names — covering identical content; (b) recruit 4–6 practitioners matching the stated audience (`docs/workshop-design.md` lines 9–14); (c) randomize to harness-exercise vs. guide; (d) measure with a transfer task on an unfamiliar fixture plus a structured explain-your-config interview, same rubric, blind grader; (e) accept that n=4–6 is a pilot signal, not proof — which is still infinitely more than the current n=0. The repo's own vocabulary applies: Module 01's central claim was rewritten after its negative control contradicted it (`docs/decisions.md` 2026-07-03, Module 01 panel row). The workshop's *own* central claim has never been given its negative control.

### Finding 2: The accumulating "fresh agent" evidence sits in the slot where learner evidence should be, and it actually cuts *against* the hypothesis, not for it — a conclusion nobody has drawn

- The 2026-07-07 Codex spike, the 2026-07-08 devstral convergence, and the 2026-07-08 Module 03 second-harness spike are consistently framed as closing the "genuinely fresh, uninvolved attempt" gap (`docs/next-actions.md` lines 144–148, `docs/module-03-pilot-completion-plan.md` Phase A). But an autonomous agent completing an exercise cold is not a proxy for a cold *learner* — it is a demonstration that **every module gate can be fully satisfied with zero human learning occurring.** The gates are artifact-based (`modules/README.md` arc table); a skilled human and an unattended agent produce indistinguishable artifacts.
- `docs/agent-native-interaction-plan.md` §6 sets the standard itself: "If the pilot can't demonstrate the human still did the load-bearing thinking, it has *disproven* the feature for that module, which is a valid and useful pilot outcome, don't paper over it." Phase A demonstrated exactly the opposite of load-bearing human thinking — the agent designed the boundary, implemented the feature, wrote the notes, graded itself. By the plan's own stated criterion, the pilot's result to date leans toward the learning-theatre outcome for agent-driven Module 03, and no document (retro, decisions row, next-actions entry) registers this. The retro (`runs/2026-07-08-module-03-second-harness-spike/retro.md`) scores rubric criteria diligently but never asks the plan's own §6 question.
- The only defenses against learning-theatre are `attempt_driver` plus the attestation-of-understanding meaning of `human_confirmed` — which the project's own panel confirmed is enforced by instruction only, with no hook or CI reading the field (`docs/review-panel/2026-07-04-module-03-manifest-pilot-content.md` finding 1). Known, disclosed, but its interaction with Finding 1 is not: the *only* mechanism that could distinguish "human learned" from "agent performed" is the one mechanism that is both unenforced and (Phase B) still unexercised three days after being declared the next step.

### Finding 3: Three of five modules' central claims failed their own negative controls — individually documented with real honesty, but never aggregated into the systemic conclusion they support

The individual results, each honestly written up:
- **Module 01:** the naive prompt passed 3/3 — the fixture's own docstring lists the edge cases, so the disciplined prompt was unnecessary (`runs/2026-07-03-module-01-dry-run/README.md` lines 21–29; claim rewritten).
- **Module 03:** the notes file was not load-bearing — the withheld-notes control succeeded from code and tests alone, in the 2026-07-03 dry run, again in the 2026-07-04 manifest dry run, and again in the 2026-07-08 Codex spike (`modules/03-harness-engineering/README.md` line 50; retro line 82ff). Three harness/session combinations, same result.
- **Module 05:** prompt- and context-sabotage failed to reproduce in 10/10 independent runs (`modules/05-synthesis-capstone/README.md` line 50); capstone honestly scoped to 2 of 4 layers.

What no document says: this is one finding, not three. **The shared `receipts` fixture is too small and too self-documenting for the taught disciplines to be *necessary*.** A capable agent (or learner) routes around a bad prompt, missing notes, or misleading context by reading a codebase that fits in one gulp and documents itself. The modules therefore currently teach the *mechanics* of each discipline while their own controls show the discipline's *value* is not demonstrable on this fixture — a learner can pass every gate while ignoring the lesson each module exists to teach. This matters doubly for Finding 1: any future human trial run on this fixture inherits the same ceiling; the harness condition can't outperform a written guide at teaching judgment the exercise never actually requires. `docs/next-actions.md` line 156 gestures at a re-audit of two old variants; nothing proposes the fixture-adequacy decision itself (grow the fixture until notes/curation/prompt discipline become load-bearing, or scope module claims down to mechanics).

### Finding 4: The 2026-07-08 spike retro contains a concrete false independence claim, and the spike's design staged the very weakness it then reported as a discovered finding

- `runs/2026-07-08-module-03-second-harness-spike/retro.md` lines 24–26 credit Codex with an Enforcement Note "matching (independently, since it never read) the module's own README warning" about unenforced custom instructions. Not independent: the orchestrator's phase-1 prompt, as literally specified in `docs/module-03-pilot-completion-plan.md` lines 68–71, *told* Codex "your own translation-table entry in README.md is unenforced custom-instructions-scoped prompt text, not path-level sandboxing, so say so plainly rather than overclaiming." The honesty was injected, then credited to the agent. Small, but it is exactly the class of overclaim this project's Skeptical Critic persona exists to catch, and it survived into a merged retro.
- Same plan, same prompt block: phase 1 is instructed to "Implement group_expenses_by_category and wire a --by-category CLI flag ... Run the tests yourself before stopping. Then stop." A phase 1 ordered to finish and verify everything guarantees phase 2 has nothing substantive to resume — which the retro then reports as a finding ("phase 1 had already fully implemented and tested the feature before stopping," lines 38–43). The module's own rubric anticipates this failure mode by name: "if the second session's job is just to transcribe what the first session already wrote in full, this criterion isn't demonstrated, it's staged" (`modules/03-harness-engineering/README.md` line 21). The pilot's prompt engineering staged it. The fix is cheap: instruct phase 1 to stop at a genuine judgment point (e.g., after the design decision but before wiring the CLI flag) rather than after full verification.
- To be fair: the same retro also produced the genuinely valuable read-boundary finding (Codex's sandbox restricts writes, not reads; the negative control read the forbidden 2026-07-04 solved checkpoint). That finding is real, was independently verified against transcript events, and is correctly flagged for Phase C. This review does not dispute it.

### Finding 5: The review apparatus is a single-model-family echo, with one narrow exception, and no document states this as a limitation

- All seven Workshop Review Panel personas, across all ten panel runs, execute on the same model family that authored the content under review: every review-run ledger entry records `engine: claude-sonnet-5` (`runs/run-20260704-AEW-004.yaml` through `-007.yaml`, `run-20260703-AEW-001.yaml`, etc.). Seven personas are seven prompts, not seven reviewers; they share one set of model-level blind spots with each other *and with the author of the material they review*. The panel demonstrably catches real issues (fixture bugs, drift, overclaims) — but what it systematically cannot catch is anything Claude-shaped: framings that seem natural to this model family, difficulty calibrations tuned to its capabilities, rubric language it finds easy to satisfy.
- The one genuine cross-family check — the qwen2.5:14b blind judging panel (`docs/risks.md` RISK-0004, 2026-07-07 addition) — is correctly described as narrow (one rubric, two transcripts, one reproduced run) and is a grading check, not a content review. Codex and devstral appear only as exercise-*takers*, never as reviewers. No panel report or risk entry names "all reviewing personas are one model family, the author's own" as a standing limitation; RISK-0004 comes closest but frames the gap as human-vs-agent, not model-monoculture.

### Finding 6: The project's human-facing governance documents are stale or empty boilerplate — ironic for a project whose named bottleneck is human review

Items the project's own self-assessment has missed entirely:
- `docs/human-understanding-check.md` and `docs/depth-decision.md` are unfilled template stubs ("Strategic rationale.", "Item 1", "Item 2") — never populated across nine material sessions, in a project whose central open risk is that no human understands the evidence independently.
- `docs/project-walkthrough.md` — the rolling plain-English explainer the CLAUDE.md contract requires be kept current — is frozen at ~2026-07-03 state and now materially wrong: it says the site is "not yet live" (live at terminal-velocity.coderturtle.io since 2026-07-04), the agent-native manifest is "researched but not built" (built and dry-run 2026-07-04), and Module 04's extensions are "not yet exercised" (verified 2026-07-04).
- `docs/walkthroughs/` contains only two 2026-07-03 entries despite the Plain-English Walkthrough Contract requiring one per material session; 2026-07-04 (five confirmations, extensions, variants, live deploy), 2026-07-07, and 2026-07-08 have none.
- Risk-register drift: `docs/risks.md` lists RISK-0001 through RISK-0006, but `.hekton/risk-register.yaml` omits RISK-0002 and RISK-0003 entirely. RISK-0002 (push credential) is still marked "Open" in `docs/risks.md` although `docs/next-actions.md` line 220 records it fixed 2026-07-03 and `main` is currently in sync with `origin/main`.
- The pattern matters beyond hygiene: the agent-writable evidence trail (`runs/`, `decisions.md`, retros) is meticulous, while every artifact whose purpose is *human* comprehension has decayed. That is the learning-theatre risk expressed in the project's own operations.

### Finding 7 (prioritization, not a new fact): the project keeps choosing agent-runnable work over the human-gated work it has itself identified as the bottleneck

Phase B — the single cheapest open item, explicitly "blocked on you, not on more agent work" — has been the declared next step since 2026-07-04 (`docs/next-actions.md` lines 149–151), while three further agent-side evidence campaigns (judging panel, Codex spikes, vulnerability runs) shipped around it. Each was individually reasonable; collectively they reveal a selection effect: work that an agent can complete autonomously gets done, work requiring human attention accumulates. Since Findings 1 and 2 both terminate in "only human evidence can move this," the selection effect is now the project's rate-limiting risk, not any individual open item.

### What this review checked and found adequate

To be explicit, per the brief's instruction not to manufacture findings: the hedging of the hypothesis in published prose is consistent and honest everywhere it appears (`README.md` line 41, `docs/workshop-design.md` line 26, `modules/` content status notes); the RISK-0004 narrative accurately describes what the qwen panel did and did not show; the 2026-07-08 read-boundary finding is genuine and correctly evidenced; the Module 05 negative results were shipped honestly rather than buried; and the review-panel fix log checks out against the files it claims to have fixed. The problem is not dishonesty anywhere — it is that an honest, well-documented apparatus is being mistaken for progress on a claim the apparatus does not touch.

## 3. Recommended next actions (prioritized, backlog-ready)

1. **Design and run the minimum viable pedagogy test for one module (03 or 04): write the written-guide control version, recruit 4–6 real practitioners, randomize harness-exercise vs. guide, measure with a transfer task on an unfamiliar fixture plus a blind-graded explain-back.** Why: it is the only action on any list that tests the workshop's central claim; everything else hardens the apparatus around an unrun experiment. Until it runs, relabel the hypothesis in `docs/workshop-design.md` from "a hypothesis this workshop is testing" to "a hypothesis this workshop is not yet able to test," which is the true current state.
2. **Do Phase B now, before any further agent-side evidence work.** Why: cheapest open item, blocks Phase C, is the sole existing mechanism distinguishing human learning from agent performance, and its continued deferral while agent campaigns ship is itself evidence of the selection effect in Finding 7.
3. **Add an explicit "mechanism vs. pedagogy" evidence split to `docs/workshop-design.md` and stop counting fresh-agent completions toward learner-side evidence anywhere.** Why: the Codex/devstral results are being framed as closing the "fresh, uninvolved attempt" gap when they demonstrate the opposite — that gates pass with zero human learning; per `docs/agent-native-interaction-plan.md` §6's own criterion, record that the agent-driven pilot has so far demonstrated the learning-theatre outcome, not refuted it.
4. **Make the fixture-adequacy decision as one aggregated finding: either grow `fixtures/receipts/` until notes, curation, and prompt discipline become genuinely load-bearing, or scope each module's claims down to mechanics.** Why: three of five modules' central claims failed their own negative controls for the same structural reason; any future human trial on this fixture inherits that ceiling (Finding 3).
5. **Correct `runs/2026-07-08-module-03-second-harness-spike/retro.md`'s "matching (independently...)" claim, and redesign the Phase-A phase-1 prompt to stop at a genuine mid-task judgment point rather than after full implementation and verification.** Why: one is a factual overclaim in the record; the other structurally stages the weak reset-and-resume the module's own rubric calls out as "staged, not demonstrated" (Finding 4).
6. **Run one review-panel pass with a non-Claude model family (Codex or the local qwen substrate already proven for judging), and record the model-monoculture limitation in the panel's own definition.** Why: ten panel runs on the author's own model family cannot surface Claude-shaped blind spots; the repo already has proven cross-family plumbing (Finding 5).
7. **Add a structured learner-feedback channel: an issue template capturing module, harness, attempt outcome, and time spent, plus an invited `runs/`-entry PR path.** Why: the shipped product currently has no sensor for the hypothesis; even opt-in anecdotes beat the current zero (Finding 1).
8. **Fix the human-facing doc decay in one pass: update `docs/project-walkthrough.md` to actual state, fill or delete `docs/human-understanding-check.md` and `docs/depth-decision.md`, add the missing walkthroughs (or amend the contract honestly), reconcile `.hekton/risk-register.yaml` with `docs/risks.md`, and close RISK-0002.** Why: the human-comprehension layer has decayed while the agent-evidence layer flourished — the project's own thesis says that asymmetry is the failure mode to watch (Finding 6).
