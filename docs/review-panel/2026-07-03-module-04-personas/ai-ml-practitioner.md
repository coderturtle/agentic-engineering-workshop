# Persona: AI/ML Practitioner — Module 04 — 2026-07-03

**Criterion 4's hard boundary has no legitimate-test-fix escape valve, and this gap propagates into the packaged takeaway.** README: *"`tests/test_grouping.py` is out of bounds entirely: a fix that touches the test file that encodes the stop condition is not a smaller fix, it is not a fix at all."* This conflates two technically distinct failure modes: (a) rewriting an assertion to match buggy output (the gaming attempt, correctly caught), and (b) a test that is itself wrong, e.g. a typo'd expected value, a hardcoded date that predates a leap-year fix, a fixture bug unrelated to the mechanism under test. Real tickets do produce case (b). As written, the rule bans both identically, with no distinguishing test (e.g., "the fix must be justified by a written root-cause sentence that does not reference the test's *expected* value, only its *actual* wrongness"). This weakness is inherited verbatim into `.claude/commands/ticket-to-pr-ready.md` step 4 ("any test file that encodes the stop condition" is *always* out of bounds), since that command is explicitly the generalized template meant to run against future, unrelated bugs, the false-negative risk (a genuinely correct fix rejected because it happens to touch a broken assertion) is real there in a way it isn't for the single-fixture exercise, where the ticket is engineered so the fix never needs to touch the test. The module should note this is a deliberate simplification for pedagogical purposes, or the takeaway command should carry a documented exception path.

**"Smallest-fix discipline" is operationalized as file/domain scope, not diff minimality**, despite the word "smallest." Grading.md's checks are file-boundary checks ("Diff is one file... Parsing, error handling, and the CLI are untouched"), not a line-count or minimal-diff metric, reasonably checkable here, but the criterion name overpromises precision it doesn't define (would a correct two-line fix padded with three unnecessary lines still pass? unclear).

**Loop taxonomy** (modules/README.md) is coherent as a mental model but mixes axes: verification/hill-climbing form a sophistication hierarchy, while event-driven is an orthogonal triggering concern, not a "layer" above verification. Minor, and inert until the event-driven extension is authored.
