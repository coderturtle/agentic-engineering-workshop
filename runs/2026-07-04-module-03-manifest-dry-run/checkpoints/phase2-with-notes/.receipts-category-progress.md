## What was done this session
Wired the `--by-category` flag into `receipts/cli.py`:
- Added `group_expenses_by_category` to the existing
  `from receipts.grouping import ...` import line.
- Added `parser.add_argument("--by-category", action="store_true", ...)`,
  a boolean flag alongside the existing `--tz` option (not mutually
  exclusive with `--tz`; `--tz` is simply ignored when `--by-category` is
  set, since category grouping has no timezone dependency — this matches
  how `group_expenses_by_category` itself was already written with no `tz`
  parameter).
- Branch in `main()`: if `args.by_category` is set, call
  `group_expenses_by_category(rows)`; otherwise fall back to the original
  `group_expenses_by_month(rows, tz=args.tz)` call, unchanged.
- Renamed the loop variable from `month` to `key` when printing bucket
  results (`for key in sorted(result.months): ...`) since it's no longer
  always a month — the print format itself
  (`f"{key}: {summary.count} receipt(s), total ${summary.total:.2f}"`) was
  left exactly as it was for the by-month path, satisfying the test's only
  assertion (that `"meals:"` appears in stdout) and keeping default
  (no-flag) output byte-for-byte identical to before, since the by-month
  branch's code path and format string are unchanged.
- Manually verified (outside the unittest, via
  `python3 -m receipts.cli data/sample_receipts.csv` and
  `... --by-category`) that:
  - default invocation still prints "YYYY-MM: N receipt(s), total $X.XX"

## Decisions / reasoning worth knowing
- `--by-category` and `--tz` are not mutually exclusive at the argparse
  level. Making them mutually exclusive (erroring if both are passed) was
  considered but rejected: the task only requires the flag to work, the
  test doesn't check for interaction errors, and adding validation here
  would be scope creep not requested by the task. If a future task wants
  stricter validation, that's a deliberate follow-up, not an oversight.
- Did not rename `GroupResult.months` (still named `months` even for the
  category-grouping path) — consistent with the reasoning already recorded
  in `receipts/grouping.py`'s docstring from the prior phase: renaming would
  ripple into `group_expenses_by_month` callers for no functional gain.
- Kept the print format string identical between the two modes (no special
  "by category" header or different formatting), since the test only checks
  for substring `"meals:"` in stdout and the SPEC didn't call for a distinct
  format. If a future reviewer wants a clearer heading distinguishing
  month vs. category output, that's a presentation choice for a later pass.
