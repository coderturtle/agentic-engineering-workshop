## Phase this note covers
Phase 1 of a two-phase reset-and-resume exercise. Scope for this phase was
narrowed on purpose: implement the grouping function ONLY, do not touch
`receipts/cli.py`, do not wire the `--by-category` flag. That wiring is
explicitly deferred to a later phase/session.

## What's done
- `group_expenses_by_category(rows)` is implemented in
  `receipts/grouping.py`, following the same pattern as
  `group_expenses_by_month` in the same file:
  - Reuses `_parse_row(row)` to validate/parse `timestamp_utc` and `amount`
    and to surface `RowError`s for malformed rows into `errors`, without
    stopping processing of the remaining rows.
  - Unlike `group_expenses_by_month`, the bucket key is `row.get("category", "")`
    rather than a timestamp-derived "YYYY-MM" string — category grouping has
    no timezone dependency, so `_parse_row`'s parsed timestamp is validated
    but not used as the key.
  - Returns `GroupResult(months=..., errors=...)`, reusing the same
    `GroupResult`/`MonthSummary` dataclasses as the month-based function
    (the `months` field name is a known slight misnomer here — kept as-is
    per the existing docstring in the file, to avoid a rename that would
    ripple into `group_expenses_by_month`'s callers).
- No changes made to `receipts/cli.py` — the `--by-category` argparse flag
  is still unrecognized by the CLI. This is intentional for this phase, not
  an oversight.
- No changes made outside `receipts/` (confirmed via `git status --porcelain`
  from `fixtures/receipts/`, which shows only
  `fixtures/receipts/receipts/grouping.py` modified).

## Decisions / reasoning worth knowing
- Chose not to apply any timezone conversion for the category key, since
  category is a direct field on each row, independent of the timestamp.
  `_parse_row` is still called (not skipped) so that malformed rows are
  still caught and diverted to `errors`, matching the required edge-case
  behavior from SPEC.md (only the categorization key differs from the
  month-based function, not the validation/error behavior).
- Left `GroupResult.months` field name as-is (not renamed to something
  like `buckets`) per the pre-existing docstring's own note — a rename
  would be an unrequested refactor touching more surface area than needed.
- Deliberately did NOT touch `receipts/cli.py` in this phase, per explicit
  scope override for this session. Do not treat the CLI test's ERROR as a
  regression to fix reflexively — verify against this note's description
  of intended scope first.
