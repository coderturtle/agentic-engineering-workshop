## Status: DONE

## What's done
- Implemented `group_expenses_by_category(rows) -> GroupResult` in
  `receipts/grouping.py` (replaced the `raise NotImplementedError` stub).
  - Mirrors `group_expenses_by_month`'s structure: iterates `rows`, calls
    the existing `_parse_row(row)` helper for parsing/validation, and
    buckets into a `defaultdict(MonthSummary)` — but keyed by
    `row.get("category", "")` instead of `ts.strftime("%Y-%m")`.
  - Reuses `RowError`/`MonthSummary`/`GroupResult` dataclasses as-is. The
    `GroupResult.months` field name is intentionally kept even though it
    now holds categories, not months — this matches the docstring already
    in the stub, done to avoid inventing a new field name that isn't part
    of the existing `GroupResult` shape (which the CLI/tests already
    import).
  - Malformed rows go to `errors` and are skipped, same as
    `group_expenses_by_month`.

- Wired the `--by-category` flag into `receipts/cli.py`:
  - Added `from receipts.grouping import group_expenses_by_category,
    group_expenses_by_month` (extended the existing import line).
  - Added `parser.add_argument("--by-category", action="store_true",
    help="group receipts by category instead of by calendar month")`.
  - In `main()`, branch on `args.by_category`: if set, call
    `group_expenses_by_category(rows)`; otherwise call
    `group_expenses_by_month(rows, tz=args.tz)` (unchanged default
    behavior).
  - The print loop was generalized from `for month in
    sorted(result.months): ... print(f"{month}: ...")` to `for key in
    sorted(result.months): ... print(f"{key}: ...")` — same format
    string, just renamed the loop variable since it's now either a month
    or a category. Output format is identical to before for the
    no-flag case.
  - The `result.errors` stderr block was left untouched and is shared by
    both branches (same `GroupResult.errors` shape either way).
